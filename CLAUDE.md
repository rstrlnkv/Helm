# Helm — how to work here

Orders, each with the reason it exists. `ARCHITECTURE.md` is the twin that describes how Helm is built; nothing here repeats it. A rule that arrives without a reason is litter — delete it.

## Commands

- Run `swift test` for the whole suite and `swift test --filter '<Name>|<Other>'` for one family — a filtered run is seconds against minutes, which is what makes running a guard before the suite cheap enough to actually do.
- Do not chase the three red guards in `Tests/HelmRuntimeTests/TheMapNamesRealDirectoriesTests.swift` and `Tests/HelmRuntimeTests/TheDocumentsDoNotDriftTests.swift` — they read the documents in the shape these documents no longer have: one looks for a table of directories where `## Where things go` now gives orders, one holds size floors the corpus no longer reaches after the measurement passages left the repository, and one compares a pair of files belonging to a crew that is gone. They go green when the guards are rewritten, not when a document is edited, so a document changed to satisfy them is a document made worse.
- Read the whole `swift test` log and its exit status, never its tail — `swift test > log 2>&1; echo "EXIT=$?"`, then `command grep -cE 'with ([0-9]+ tests? skipped and )?[1-9][0-9]* failures?' log` to find where, and `command grep -c 'warning: No matching test cases were run' log` after any `--filter`: the closing "All tests passed" is about the last bundle and not about the suite, a summary line that also carries a skip count reads as zero failures under the shorter pattern, and a `--filter` whose name matches nothing exits 0 with every bundle reporting "Executed 0 tests".
- Build one target while working with `swift build --target <Name>`, and a release only as `swift build -c release --product HelmApp` — a bare `swift build -c release` also builds the test-support target, which imports XCTest out of the Xcode-only framework path and lands beside the app; `Tests/HelmAppTests/ReleaseBuildsTheProductTests.swift` holds both halves.
- Package with `bash Scripts/package-app.sh` and install only from the signed copy it stages under `$TMPDIR` — that is the bundle the script signed and verified, while `.build/` holds an unsigned one with no usable identity at all.
- Use `bash Scripts/package-dev.sh` for a build to click through by hand — it installs beside the real app with its own bundle id and its own settings domain, so a manual check does not cost the installed app its grants.
- Read the shipping version with `/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' Resources/HelmApp/Info.plist` — that key is the number the updater compares, and every other place the number appears is derived from it.
- Run `plutil -lint Sources/HelmUI/Resources/*.lproj/Localizable.strings` after any hand edit — a malformed file is silent, and every string in it falls back to English with no error anywhere.
- Run `swift test --filter 'PunctuationIsTerminologyTests|StringsCoverageTests|NoOrphanTranslationsTests'` after touching a `.strings` file, before the suite — those three are the guards a string change trips, and they finish in seconds.
- Keep `command grep -rn HELM_DEBUG Sources/` empty before every commit — the visual harness is env-gated and belongs in the working tree only while it is being used.
- Answer "who uses this" from an index and never from `grep` — this tree writes backticked names inside doc comments deliberately and at volume, so a grep counts prose as a caller; run `swift build --build-tests`, then `periphery scan --skip-build --index-store-path "$PWD/.build/out" --format csv`. Do not read that report as a to-do list either — its "unused" covers dead code, a marker a test checks by type rather than by call, and a fake's capability no test has needed yet, while its assign-only findings are usually a property held to keep an object alive, a token whose clearing is the cancellation, or a field a synthesized conformance reads.
- Read `~/Library/Logs/Helm/helm.log` rather than assuming — its `[permissions]` line is where the installed build says which grants it actually holds.
- Measure before believing a cleanup — `du -sh "$TMPDIR"` first, then check what under there is not `helm-*`, because the same folder holds other programs' files; pass `--scratch-path` only when another suite run may be up and reuse one path for the session, since a fresh directory per invocation is over a gigabyte that nothing sweeps while the machine stays up.

## Before you touch the code

- Read `ls Sources/HelmRuntime`, `ls Sources/HelmUI/DesignSystem` and `ls Tests/Support` before writing a helper — what is in them was spelled out in prose twice and went stale both times, and the scratch directory, the repository-root walk and the progress box were each hand-rolled in dozens of files before they moved there.
- Ask which gate answers your question before widening any reach — `RemovableScope` (`Sources/HelmRuntime/RemovableScope.swift`) answers what belongs to an *application*, `UserFileScope` what belongs to the *user*, `WatchScope` (`Sources/Modules/Autopilot/Engine/Logic/WatchScope.swift`) where an unattended rule may reach, `ScanRoot` (`Sources/HelmRuntime/ScanRoot.swift`) where a read nobody watches may begin and descend, `SSHFileScope` (`Sources/Modules/Hosts/Engine/Logic/SSHFileScope.swift`) whether Helm may *write* a path at all — the symptom of the wrong one misleads, and pointing the duplicate finder at `~/Downloads` under `RemovableScope` disabled every checkbox in its own result, which reads as a permissions problem.
- Ask of every stored reading what happened between the reading and the act, and who re-asked — that question finds this family of defects, and "is this a flag" does not.
- Ask, before storing anything derived from an event stream, which event clears it and what happens the one time that event never comes — every event carries the live modifier flags and no release is guaranteed, and one code left behind spoiled every tap from then on, permanently and silently.
- Ask where a value is read from and how often before sealing it (`Sources/HelmRuntime/SettingGuard.swift`, `Sources/HelmRuntime/SettingSeal.swift`) — on an ad-hoc signed build every keychain item is a dialog, because the cdhash changes with every build and no access list an earlier one wrote still names the program.
- Ask what a *total* failure of the thing a new check guards would print — if that looks the same as success, it is not a check yet; then put the defect back and watch it go red, because a check never seen to fail is not a guard.
- Establish who is drawing a thing before fixing it, and ask what a view's identity is across a change before touching a curve — AppKit's drag draws its own translucent snapshot, a system focus ring follows the frame rather than the shape, and a prominent button renders grey without a key window, so three fixes went into a tile underneath a system ghost; and SwiftUI interpolates between two states of one view and never between two views, so four separate "animation bugs" in one panel were one identity bug each.
- Build from a fresh `git clone` before a release — the manifest is refused whole when a declared test path does not exist, so an untracked test directory makes `swift test` work in your checkout and on nobody else's, and the working copy is not evidence.

## What not to do, and what breaks if you do

- Do not import another module's engine from a module or from the host, and do not import SwiftUI or the shared UI target from an engine — nothing falls over, the two just drift apart silently, the host's edge would be a door straight past the transport into an engine's internals, and an engine that draws cannot be tested headless; keep AppKit to system calls in that module's own ports file, which is what a fake stands in for.
- Do not type a module id as a literal — read it from the engine's own identifier, because a namespace that disagrees with its descriptor's id does not fail, it reads a different store, which answers with defaults and looks to the person like their settings were forgotten.
- Do not put a `default:` arm on a module command switch, and do not restate a command's payload type on the view-model side — an unhandled case has to be a build error, a `default` nobody re-reads makes a typo look like a refusal, and a matching struct declared twice is a wire contract with no compiler between its halves; declare the payload once in the engine's logic file and read it from the UI target, which already imports the engine.
- Do not delete anything that has not passed its module's gate **inside the engine** — the engine takes a list of strings and deletes them, so any defect upstream that produces a bad string produces a deleted folder, and an empty display name has already claimed `~/Library/Application Support` itself; never widen a scope without a test naming the new path (`Tests/HelmRuntimeTests/RemovableScopeTests.swift`, `Tests/HelmRuntimeTests/UserFileScopeTests.swift`).
- Do not keep a copy of the removal loop in a module — hand the batch to `HelmTrash` (`Sources/HelmRuntime/HelmTrash.swift`), which owns the ordering, one outcome per path, one set of file ids so a hard link's bytes count once, and the classification of what macOS said; the one module that kept its own copy reported a file taken along with the folder above it as neither moved nor refused.
- Never drop a refusal — each is a reason on `TrashFailure` (`Sources/HelmRuntime/PermissionCheck.swift`), and a refused path that reaches neither the removed list nor the failed list is announced as "Removed — N freed" over a file still sitting there.
- Do not read a folder's size from `totalFileAllocatedSize` — on APFS that answers for the directory entry and is zero, so Disk told people a folder they had just trashed freed nothing; walk it, and treat a clone family as one when counting what a removal returns (`Sources/HelmRuntime/CloneShare.swift`), because Finder's Duplicate command makes clones and a group of them promises double the space the disk will give back, while a file whose family id cannot be read counts as its own since under-reporting is the safer error.
- Do not act on a reading older than the act — re-read the pair immediately before anything moves in Duplicates (`Sources/Modules/Duplicates/Engine/DuplicateVerification.swift`), where the offer on screen is minutes or a day older than the press and only the survivor's reading may be memoised, and re-ask whether an app is still running after the quit loop (`Sources/Modules/Uninstaller/Engine/Logic/UninstallPlan.swift`), because macOS moves a running app's bundle without a word, the process carries on and writes its preferences when it finally exits, so the leftovers just taken come back and the removal reports itself clean.
- Do not treat a path a glob or a bundle id produced as a finding — filter it two ways against what is actually installed (`Sources/Modules/Uninstaller/Engine/Ports.swift`), since a prefix glob matches a neighbour's app and an exact candidate can belong to an app that declares somebody else's bundle id in its own information property list.
- Do not read the running-apps quit port as though it named one app — it quits every copy running under that id, so ticking `/Applications/Foo.app` force-quits a copy running from `~/Downloads` with unsaved work.
- Never let a privileged command carry the path of a staged file instead of its content — the path stands in `ps auxww` for as long as the password prompt is up and any process running as this user can swap the file between the prompt and the write, which is how a syntax check could have been passed with a passwordless-root rule (`Sources/Modules/Hosts/Engine/Logic/HostsWrite.swift`, `Sources/Modules/KeepAwake/Engine/Logic/SudoersRule.swift`).
- Keep base64 as the gate on anything crossing into root's AppleScript literal — its alphabet holds no quote, dollar, backtick, semicolon, backslash or newline, which makes injection unrepresentable rather than unlikely; escape through `Sources/HelmRuntime/AppleScript.swift` and nowhere else, backslash before quote, because the other order escapes the backslash the call had just introduced and an unescaped quote hands everything after it to a shell running as root.
- Count the decoded bytes before the redirect exists, never after — redirection truncates first, a pipeline's status is its last command's, and a decoder reading end-of-file exits zero, so a check after the write reported success over an emptied `/etc/hosts`.
- Never make a string of a secret, and never put one in the argument vector, the environment, a file or the log — a string is a copy this code cannot overwrite, and `Sources/Modules/Hosts/Engine/PTYProcess.swift` takes it in-out and zeroes it on every path out, including a failed spawn and a deadline; silence the terminal echo yourself when answering a prompt on a pseudo-terminal, or the passphrase comes straight back in the transcript.
- Never point key generation at a name already in the directory (`Sources/Modules/Hosts/Engine/Logic/KeyGeneration.swift`) — the tool asks whether to overwrite and this design answers prompts, so an answer meant for a passphrase lands on that question and destroys a key nobody offered to replace.
- Do not add a rule under `/etc/sudoers.d` for anything reachable another way, and do not add a script action to Autopilot — a permanent passwordless root grant is worth paying only for something otherwise impossible, and the rules live in a property list any process running as the user can write, so a script action turns "a file appeared" into arbitrary execution; make any grant carry its own revocation, argument-exact and one literal path — except `/opt/homebrew`'s ownership change, which has none, because Helm cannot know what the ownership was before and the new ownership is what the installed program needs — because dragging an application to the Trash runs no code; but raise no dialog on the way out, since a global-queue dispatch from a terminating process either never runs or asks for a password during quit with nothing on screen to explain why, so a rule too old to withdraw itself is left where it is.
- Bind a per-app rule to a code signature and never to a bundle identifier (`Sources/HelmRuntime/CodeIdentity.swift`, `Sources/Modules/VPN/Engine/Logic/VPNRuleTrust.swift`) — the identifier is a string in a property list any bundle can carry, so anybody's build naming a watched id can launch and take a tunnel down; a rule with no recorded identity refuses.
- Keep names out of the log and out of any file that names somebody's files — VPN, app, package and path values go through `Sources/HelmRuntime/Redact.swift`, and a file is written through `Sources/HelmRuntime/PrivateFile.swift` rather than a hand-rolled atomic write plus a mode change, because the journal is readable by any process running as this user including ones macOS refuses, and an atomic write renames a new inode into place so the mode belongs to the write and not to the file.
- Seal any stored setting that steers unattended work and let a broken seal refuse in the safe direction, but never refuse to *save* what a person asked for — the property list is writable by any process running as the user, so an unsealed setting is somebody else borrowing Helm's Full Disk Access, while failing at the writer is the wrong end to fail at.
- Do not seal a setting that any initialiser reads, a SwiftUI state's initial value included — that is a keychain dialog in front of a window that has drawn nothing, on every install; seal what is read occasionally, spend first use at the getter's early return so a planted value is never adopted before the guard is touched, and cache the key but never the verdict, since the key cannot go stale while whether a stored value is the app's own is a live fact about a file anything can rewrite.
- Never treat a missing seal as the sign that a migration is due — only a missing keychain key is (`Sources/HelmRuntime/KeychainSealKey.swift`), because a seal is data sitting beside the rules it signs and an attacker who can write the file can delete the seal too; and never write anything back from a refused read, since the editor once drew a tampered rule set the way it drew none and the next ordinary save sealed that emptiness with Helm's own key.
- Do not write a new keychain item for a mechanism that already has one deployed — Autopilot's exists on every Mac that has run the module, and moving it reads there as "somebody rewrote your rules"; give a new setting a new account instead.
- Take one lock over reading the rules, judging them against the seal and recording that judgement, and another over saving payload and seal — those reads come from the sweep timer, from file-system events, from the transport and from the watch refresh, and unordered they let "these are Helm's own rules" land on top of "something else wrote these", while a read landing between the two writes of a save judges new rules against an old seal and calls Helm's own work tampering (`Tests/Modules/Autopilot/EngineTests/AutopilotSealRaceTests.swift`; before it the failure was one run in thirty under load). Take the lock on both sides of any such field, in a synchronous property that returns the value rather than holding it across a suspension.
- Judge a descent by the directory's *name* and never by reading it — reading a directory to decide whether to read it *is* the Photos consent prompt, and package-descendant skipping is no substitute because it asks whether the type is registered on *this* Mac; ask the gate of every directory a walk meets and not only of the root (`Sources/Modules/Duplicates/Engine/DuplicateScanner.swift`), since the home is the intended root and the very first descent reaches the subtrees the rule exists to keep out.
- Strip the `/private` prefix from both sides before comparing a walk's paths against a root, and compare a path against a protected prefix in both spellings — the enumerator resolves the root's own symlinks on the way out, and path standardization rewrites one spelling to the other only for a path that **exists on disk**, so a gate comparing raw strings matches nothing and fails open, silently, which is the worst way for a gate to be wrong; test such a gate with paths that exist, or it is tested on the one input the filesystem treats differently.
- Never record a nil report as an empty one, and record an attempt and a completion as two facts with the attempt written before the work — "we looked and it was clean" is the sentence a person decides whether to trust the app on, and a scan that came back with nothing because the root was refused must not spend the whole day's budget.
- Never touch the workspace's running-applications or frontmost-application readings off the main thread — AppKit copies a mutable array under a lock while the main thread mutates it, so an overlap is a crash rather than stale data; go through `Sources/HelmRuntime/RunningApps.swift` and `Sources/HelmRuntime/FrontmostApp.swift`, which refresh on main and hand every other thread a snapshot, and treat moving work off the main thread as a change to every AppKit call it can reach, because Layout's fix gesture took eight call sites with it and went down on the first use with text selected.
- Read the exit status *and* the standard output of a network-configuration query together before announcing anything (`Sources/Modules/VPN/Engine/Logic/VPNCommandReply.swift`) — the tool exits zero whatever happens and puts its answer on standard output, so a start against a renamed configuration failed in total silence; and do not prune a per-configuration book on one such read, because it answers short or not at all on a refusal or a Mac mid-boot.
- Give a read-only query a deadline and let a long operation stream without one (`Sources/Modules/Homebrew/Engine/SystemPorts.swift`) — a hung tool waiting on somebody else's lock has to end inside the same sitting, while ending a build halfway is how a Cellar gets broken; keep the last answer when a query times out and say so in the log, since "no packages" drawn over a full Cellar is a lie about the machine, and halve a batch on retry rather than the timeout, because each half of a split deadline hangs for the same full term.
- Read the parse of a hosts file as a *reading* and never as the document (`Sources/Modules/Hosts/Engine/Logic/HostsFile.swift`) — it carries comments, alignment and lines this parser does not model, and a round trip quietly reformats the file that decides where somebody's traffic goes; keep known-hosts lines byte-for-byte and edit only by dropping one whole (`Sources/Modules/Hosts/Engine/Logic/KnownHostsFile.swift`), because a line there is somebody's public key and this app has no business re-spelling one.
- Never launch a process directly — the launch call raises on some paths, an Objective-C exception has nothing to land on in a Swift frame, and the process aborts; go through the guard in `Sources/HelmLaunch`, which has no Swift frame between it and the raise, and catch whatever it raises rather than forbidding what is known to raise, because the crash in the field came from a path nobody had enumerated; and hop any blocking call through `Sources/HelmRuntime/OffTheCooperativePool.swift`, since a transport handler runs on the Swift-concurrency pool and a process waited on or a recursive scan parks a pool thread for seconds.
- Read standard output before waiting for the exit, and give a descriptor nobody reads the null device rather than a pipe — the child fills the pipe, blocks in its write and never reaches the exit the wait is waiting for, and a tool with a warning per item passes sixty-four kilobytes without trying.
- Split a stream on the newline *byte* and decode only complete lines, and end the stream when the pipe is empty rather than when the child exits — a read splits on byte boundaries, so decoding each chunk discards the whole chunk for one character straddling a read, and clearing the readability handler at termination drops the last line the tool printed; a test with an instant consumer passes over both.
- Keep standard error in a stream a person reads and out of anything that gets parsed — a merged warning becomes a row with a button on it. Keep a ceiling on how many tools are out at once and let the excess queue, and never put an unbounded launch behind a control a person can press repeatedly.
- Put an `autoreleasepool` **inside** any loop that reads file contents in bulk and never around it — a file read hands back an autoreleased buffer, a concurrent-perform loop drains no pool per iteration, and one large file is a single iteration of the caller's work, so without one the footprint tracks the volume read rather than the slice size; do not add one to a resource-values loop, where the values bridge to small types, and keep that negative measurement as a test (`Tests/Modules/Duplicates/EngineTests/WalkFootprintTests.swift`) rather than a sentence, or the next reader re-derives it or adds a pool nobody needs.
- Measure a per-object cost against the allocator's own books and a process's cost against the footprint reading, and never attribute a memory peak to a neighbouring log line — the allocator keeps its tools out, so a footprint can stay flat across a fill that really did allocate; find the same signature in a run where the suspect was idle, and the log that raised the suspicion usually holds the run that settles it.
- Do not store a composed path on a node, and do not compose in a breadth-first stack of node-and-path pairs — a string over fifteen bytes leaves the struct for the heap and a node count multiplies it, and the stack hands the same cost back as a transient spike; compose from the name during a recursive descent from a known root, through `Sources/HelmRuntime/ScanPath.swift`, and join with its child helper, because a doubled slash is inherited by every descendant and the firmlink skip set then stops matching in the one case it exists for. Never convert a device identifier to an unsigned type; it is signed.
- Bound any record that grows for the life of the app — `Sources/HelmRuntime/LogTail.swift` at a thousand and `Sources/Modules/Autopilot/Engine/Logic/ActionHistory.swift` at five hundred are the two shapes; a console fed by every event and cleared only by a button is a leak with a scrollbar, and each line is also a view.
- Stop every observer a module starts in its deactivation **and** give the object a `deinit` — dropping the engine leaves anything still holding a pointer into what the engine owned holding freed memory, and deactivation is not guaranteed to run; refuse to bootstrap a module that is already live, because assigning a fresh engine over a live one leaves a keyboard tap on the run loop and power assertions held, and the `deinit` is what makes the *next* unnoticed route survivable rather than the fix for this one.
- Do not "fix" an unretained C context by retaining it — a retained context keeps the object alive until the port is invalidated and only the object's own teardown invalidates it, which is a cycle in which a switched-off module goes on reading every keystroke; remove a run loop source **and** invalidate it, because removal takes it off this run loop while invalidation stops the callback already scheduled, which is the one that lands on the freed object. Cancel a subscriber task from the class's own teardown and not from `deinit`: a task capturing self weakly resolves that capture once, and the method it then calls holds self as strongly as any call on the stack, so `deinit` cannot run while the task is alive.
- Read the system's own withdrawal of an observer — an event tap is disabled for timeout and for user input, and revoked when the grant is withdrawn, announced only by an event of that type arriving down the tap being disabled.
- Never read a value out of a property list without bounding it, and put the bound in the engine rather than in the views — any process running as the user can write the preferences folder, a legal file can hold the largest integer, and an integer multiply traps on overflow in release as well as debug, while a clamp in every view is a clamp in no engine and a payload decoded straight off the wire reaches the same multiply with none of them; make the ceiling one constant every reader reads, so the trapping conversion is unreachable by construction, and bound a value read at launch as carefully as one read from a window, because a trap during launch is the app terminating with no window left to undo the bad value from.
- Clamp through `Sources/HelmRuntime/Clamped.swift` and say at each site what a not-a-number means — three hand-written spellings of minimum and maximum read as one sentence and are not, each absorbing a not-a-number at whichever bound the argument order happened to protect, and a countdown fraction has to read as finished where a ring level has to stay solid, so the two must not collapse onto one answer; when a fix adds a bound, ask which direction the tests exercise, because a relative bound proven from one side only is unproven from the other.
- Say in a port's doc comment which reasons collapse into an empty read, and give a caller that must tell them apart a second entry point or an enum naming each reason — not a convention for reading one optional two ways depending who is asking; a sentinel is the same defect, since a zero meaning "not measured yet" cannot also mean "not drawn". Do not fold an unreadable system answer toward the permissive side without asking whether the guard downstream needs the difference, or "battery with an unreadable charge" becomes decidable nowhere.
- Give any port that can change under the app a reverse channel, and let the fake stand in that state too — a local flag set once against a live external fact goes on reporting a world that has moved.
- Reload an engine's cached settings in its activation and not only on a settings-changed message — a field with no sensible initial value is bound to nothing on every launch and refuses before there is anything to log, and a test that sends the message itself cannot see it.
- Log only a refusal and never an absence — "no cached credentials" is the ordinary state after every install of an ad-hoc signed build, and warning on it sends an investigation after something that already happened; do not ship any line reporting on the state of the world without running it against an ordinary machine and counting how often it is silent, because if the answer is "rarely" the design is wrong however good the filter is.
- Open a phase with the activity registry's phase call, whose `defer` closes it on return, on throw and on cancellation — the balance-by-hand it replaces caused three cancel-path defects; use the bare begin only with a `defer` on the very next line and only where the phase is the whole body of an asynchronous function, and put the label on the shared path rather than at each call site, so all four deleting modules carry the name and a fifth cannot forget to.
- Give a bulk phase both the named interval and the memory reading, or leave it out of the trail entirely — the log is silent below a few megabytes of change, so a cheap label costs nothing and the only reason to omit one is that the work is genuinely not bulk; keep finer-grained signposts out of the registry, which is phase-level only, and never let the trail say the app is idle, because an empty registry means no *named* phase is open while the render, a refresh, an update check and a trash sweep all run outside it.
- Follow a bounded tail by the newest line's identity and never by the tail's count — the count is the limit for ever once the tail is full, and the change notification stops firing; fill the tail from the parts the file line is spelled from and parse a line back apart only in `Sources/HelmRuntime/LogSeed.swift`, which is obliged to be the exact inverse of the format, and reuse a cached date format rather than building a formatter per call, since the visible rows alone cost milliseconds of main thread per second; and give that pane's fixed-width category column an explicit line limit, because three module names are wider than it and a wrapped name doubles the row.
- Write every user-visible string as a lookup on its English text and add the key to all eight localization folders — the English text *is* the key, and `Tests/HelmUITests/StringsCoverageTests.swift` fails when the eight diverge; write different English when you need the same word for a second meaning, because one key means one thing and several languages had drawn distinctions the English had lost.
- Never spell a control's label by hand inside a sentence that names it, and never interpolate a verb — call the same string the control calls and interpolate that, or a rename leaves the sentence behind and all seven translations faithfully translate the wrong word; a verb inflected against eight grammars is right in roughly one of them, so each variant needs a full key with its own eight translations.
- Take quotation marks from the quoting helper in `Sources/HelmUI/L10n.swift` rather than the mark that comes to mind — the marks differ per language and writing one into all eight files is the mistake that keeps recurring; cheapest of all is an English key with no quotes, so the seven translations have nothing to copy.
- Sweep the French folder in a pass of its own after adding keys, with an explicit escape for the unbreakable space and never the literal character — French takes one before `: ; ? !` and inside its quotation marks, and a literal one does not survive a shell heredoc into Python: it arrives as an ordinary space and the substitution silently does nothing, so check the count moved with `command grep -c` before and after.
- Read a system spelling out of macOS's own bundle when a string names something macOS also names — a unit, a settings pane, a folder — and read the table that is *displayed* rather than the one that is searched: three units and four pane names were invented before anyone opened those files, and a pane's search terms are the phrases that find it and are never drawn.
- Keep an inline table argument only where the key is Swift-interpolated — interpolation runs before the lookup, so an interpolated literal can never match a table entry; `command grep -rln 'table:' Sources` is the list of sites that legitimately have one.
- Put anything the language shapes through the shared UI target — the byte, date and picker-width helpers in `Sources/HelmRuntime/HelmBytes.swift`, `Sources/HelmUI/L10n.swift` and `Sources/HelmUI/DesignSystem/PickerWidth.swift` — because a Foundation formatter built with no locale answers in the *system's* language, which on a Mac outside Helm's eight means an English interface with somebody else's dates spliced into it; never hold such a formatter in a static constant, since the app's language changes while it runs and the cache otherwise answers whichever caller asked first.
- Take every visible curve from `Sources/HelmUI/DesignSystem/HelmMotion.swift` and never write one inline — an inline curve cannot be found by anyone looking for the app's vocabulary and does not collapse under Reduce Motion, which SwiftUI does not honour for us and which is a medical setting rather than a preference; keep the reduce-motion flag a computed property, because stored in a constant it freezes at launch and the person who notices is the one who turned the setting on.
- Reveal by animating a measured height with clipping (`Sources/HelmUI/DesignSystem/HelmAccordion.swift`), never by conditional insertion and never by fading — removing rows collapses the card's background instantly while they keep drawing over what is below, a move transition paints rows over the header, and an opacity fade resolves hierarchical colours in an offscreen layer that jumps when it is dropped; inside such a block use a literal primary colour with an opacity rather than a secondary or tertiary one, for the same reason.
- Write a measured value inside the animation transaction where it lands, not where the change was triggered, and do not animate the first measurement — a geometry change hands its value over outside the running transaction, so an animation modifier on the frame it feeds is indistinguishable from none, and nil means "nothing has measured this yet", so animating up from a sentinel zero plays the view collapsing from whatever the unmeasured layout happened to be.
- Read an offered width from a sibling with no size of its own and never from the view being measured — a geometry reading reports a view's *resolved* size, so once a row overflows it reports what the row demanded and a threshold fed by it latches upward and can never come back down; measure a threshold against the widest the string can become in every language and then ask what window ever crosses it, because a control gated above every reachable width is a deleted control that still costs a constant and a test.
- Take a card from the card modifier and never draw a border, give a floating surface the glass effect and no edge, use the badge for a pill, and draw an empty page with the shared empty and busy states inside the centred-content container (`Sources/HelmUI/DesignSystem/HelmSurfaces.swift`, `Sources/HelmUI/DesignSystem/HelmBadge.swift`) — half the pages are system-drawn grouped sections that cannot be restyled, so an outlined card of our own reads as a different kind of box on the next page over; glass carries its own edge and shadow, so a hairline on top is a second silhouette; and ten hand-rolled empty pages arrived in eight shapes, each reasonable beside the screen it belonged to. Ask whether a thing needing the card's column could simply *be* a row in the card before reaching for the grouped-header outset, which backs out an inset a section row is given for nothing.
- Take a size from the type ladder and a step from the spacing or radius ladder, and ink that means something from the signal palette — a value off the ladder is a decision somebody has to argue for, a census found six type sizes across three weights before there were four, and a raw orange, green or red handed to something that paints is what `Tests/HelmUITests/SignalInkTests.swift` scans for, while a tint behind text is not ink and is deliberately not caught.
- Give every control a real name and every glyph-only control an accessibility label — an unnamed picker reads aloud as a tab group with no name and a glyph-only button reads as "button", a placeholder is not a name because it disappears the moment there is a value, and `Tests/HelmUITests/NamedControlsTests.swift` is the only thing that can see this defect at all.
- Resolve and blend a tint inside the appearance it is drawn in, and convert a colour to sRGB on the way in — a colour bridged out of SwiftUI is dynamic, so a blend one line outside the block resolves again against whatever appearance is current and darkens the wrong colour, and three bytes of another space read back as sRGB are a different colour at the next launch; retire a stored case rather than removing it, because a case that stops existing reads back as the default with no explanation on a Mac that has already run the app.
- Draw a menu swatch already coloured and leave it a non-template image, and hold a colour panel's target from the view — a menu item takes an image and drops a tint, a template is recoloured by whatever menu draws it, and the panel keeps its target weakly, so a bridge created inside the action is deallocated before the first colour comes back and reads as a panel that does nothing.
- Measure a component's contrast against what it actually draws on rather than against the page, and check a control can be photographed before choosing it for a surface this house verifies by photograph — the same ink clears the floor comfortably on a card and sits under it on a banner's own fill, so the card's reading is the one that would ship unreadable, and AppKit draws some controls outside the layer a cached display reads, so they render as nothing in a harness *and* in a real window.
- Refresh the published sets **before** a veto returns, and build them from the same expressions the behaviour consults, once — a screen drawn under a veto otherwise reads whatever the sets held when it began and offers to pause a rule that is not holding, and one screen carrying two accounts of one rule shows the quieter one, which is the one that sounds like nothing is wrong.
- Say on the wire when a guard has stopped everything, give it the one notice slot when both it and a pause are true, and gate that slot on "there is something to say" rather than on the pause flag — a session that ends with nobody touching anything leaves the log as the only place that can say who ended it and why, only one of the two explains why nothing at all is running, it carries no button because a control that cannot do what it says is worse than none, and a guard that sets no flag of its own otherwise collapses the banner to nothing.
- Keep a per-rule fact per-rule, and mark a module macOS is blocking from the declared permission rather than from the switch — a module-wide suppression marked on every switched-on rule says "paused" about rules that are merely waiting, and a page reading its own enabled flag shows "Active" for a module that has been inert all session.
- Refuse an outgoing payload equal in every field to the last one sent — a poll that re-reads many times behind one command otherwise re-renders every mounted tree per reading, while exact equality withholds only duplicates and replay still serves late subscribers.
- Unmount a page's subtree while its window is hidden rather than detaching the hosting view or pausing the view model — the attribute graph lives in the hosting view, and pausing subscriptions is wrong for a module whose banners are posted from the event handler; the idle-off-screen modifier keeps the subscription and rebuilds from current state.
- Require a gesture behind a password prompt and read the *edge* rather than the value, consuming it before the module's own active guard — a settings change arrives for every control the page draws and the value stays true after a dialog is declined, so asking on the value produces a prompt for every later unrelated edit, and an edge that happens while the module is idle must be spent rather than saved up.
- Judge completeness on every part of a value rather than the part that was easy to check, let one predicate answer the switch, the store and a hand-edited file, and never judge a scan's completeness from a flag that is true while the walk is running — a condition left blank can be an all-matcher, which with a destructive action is a working rule three gestures away; otherwise the screen and the sweep disagree about what "finished" means, and a save door taken mid-walk writes a partial result the module reopens on, labelled as measured.
- Do not rely on a defaulted property to make an older encoded payload decode — the synthesised decoding requires the coding key regardless of the initial value and gives up on the whole document rather than filling in the one field; write the initialiser by hand and read the later fields as optional-if-present.
- Make a test that measures assert something, and assert that the subject happened before asserting an absence — a test that logs a figure for a person to read cannot fail, and a real regression sits in it until somebody reads the number by hand; a test looking for a missing word passes when nothing was logged at all, which is the default in a test process because the log is off outside a dev build.
- Assert on tree *structure* and never on sizes when testing a volume-group walk — which side of a duplicate path wins is a race, so a size assertion passes by luck, and it did once; and re-run alone at least three times before believing any result found while more than one suite run was up, because the build lock serialises building and not running, and two runs share the scratch directories, the Trash and Application Support.
- Restore a mutated file from a copy and never with `git checkout` on the path — that restores to HEAD and discards every uncommitted edit in the file, which destroyed three separate pieces of work in one afternoon; better still, commit before mutating, and read the mutant back out of the file before believing the outcome, because three separate "0 failures" results in one pass were substitutions that had never applied.
- Give a fake every state the real port has and no state it does not, let it stand for one side of a boundary only, and let it finish the prompt it stands for — a simpler fake makes the failure unrepresentable rather than untested, a freer one proves a branch unreachable in production, an encoder and decoder that disagree are green against a fake that encodes its own reply, and a fake that never completes leaves the engine mid-prompt for ever behind an in-flight guard; name the fake port at every construction, because a defaulted port is the machine's own keychain and eleven forgetful constructions rolled a real rule set back.
- Use a runner that never exits when testing a busy gate, and never use a cooperative yield as a wait — a fake answering synchronously releases the gate before the call it gates returns, so the test passes with the gate deleted, and a yield buys a turn on the pool and no wall-clock time, so no number of passes widens the window a writer can land in.
- Take a scratch directory from `Tests/Support/ScratchDirectory.swift` rather than hand-rolling setup and teardown, and register a restore that must outlive the sweep as a teardown block — its teardown drains on the clock and asserts the directory is empty, where a single removal loses a race against any code that saves from a task of its own, and teardown blocks run first, so a directory left unreadable is otherwise swept before it is made readable again.
- Point a harness at a temporary folder, then delete what it saved under `~/Library/Application Support/Helm/` and check the app's own state before calling it done — real code writes, and the app has twice been handed back with somebody's test tree in it and no way out; ask whether a thing predates the session before removing anything under `/Applications`, and prove what a harness launches can replace what it kills before it kills anything. Grant Accessibility to the process at the top of the launch chain rather than to the test runner, because the system attributes the ask to the responsible process.
- Name the appearance a render is taken in, and take any reading more than once before believing it — this machine switches by the sun, so an unnamed reading is a reading of the hour and a suite has gone red between two runs with nothing committed between them, and a count taken while the suite was still building was off by ten where three consecutive runs agreed.
- Record motion with a screen recording and never wrap the recorder in a timeout — the file is written when the recording stops and the signal kills it first, which reads exactly like a permissions refusal; stills arrive at about five a second and are for settled states, and shoot by window number rather than display index, because that index is not the screen order and a full-screen capture photographs whatever else is open on somebody's machine.
- Timestamp the sampling loop of any pixel probe, anchor a measurement on something that moves with what is measured, crop to the part that moves, measure at the shipping duration, and ship the control with every ramp test — reading pixels costs enough per frame that twenty "20 ms" samples cover more than a second, a fixed rectangle over a growing page measures the page, a whole-window difference is dominated by whatever else changed, at three seconds an instant snap reads as "it drew quickly at the start", and without the control the ramp passes on a machine that animates everything by default; never measure motion from a hosting view's fitting size, which answers with the ideal size and reads every ramp as a step.
- Keep the checkout out from under a file provider (iCloud Drive, Dropbox and the like), and sign from the staged path `Scripts/package-app.sh` prints rather than in place — a provider stamps `com.apple.FinderInfo` onto the directories it manages faster than `xattr -c` clears it, `codesign` refuses a bundle carrying it, and an unsigned bundle has no cdhash for TCC to hang Full Disk Access on, so the permission comes loose on every rebuild; `$TMPDIR` is not synced, which is why the script assembles and signs there.

## Where things go

- Give a new module all four directories — `Sources/Modules/<Name>/Engine`, `Sources/Modules/<Name>/UI`, `Tests/Modules/<Name>/EngineTests`, `Tests/Modules/<Name>/UITests` — and register its descriptor in `Sources/HelmApp/ModuleRegistry.swift`; the manifest requires all four and does not read the filesystem, so a missing one is a build error on every machine rather than a module quietly having no tests. Commit at least one tracked file into a new test directory before pushing, or the manifest is refused on every checkout but yours.
- Put a string or a control two modules both draw in `Sources/HelmUI`, and test plumbing in `Tests/Support` — a fix made in one module and copied into the other is what these passes exist to undo, and the test-support target is to a test target what the runtime target is to the app; put a check for the app layer in `Tests/HelmAppTests`, since the host does take a test target and there is no reason to move code out of it to reach one.
- Make a shared helper no simpler than the thing it stands in for — the drain in `Tests/Support/ScratchDirectory.swift` is the point, and a local helper that does more keeps its own body and calls the shared one.
- Make `public` mean "another target uses this" and demote by the compiler rather than by reading — every module is two targets, so `public` is the only way across a boundary and therefore the only honest declaration of where the boundaries are; expect more than one pass, since a type turning internal makes its members' `public` redundant in turn.
- Put a hand-written list of module ids next to the thing it names, or expect it to become a comment — a module gains a background scan by conforming its engine to the scanning protocol **and** by entering the scannable list in `Sources/HelmRuntime/ScanRunner.swift`, `Tests/HelmAppTests/ListsAgreeWithTheTreeTests.swift` fails on either half alone, and a string in that list that no engine answers makes the caller read nil as "the module could not answer" while the coordinator spends a day's budget per tick on a module that has never scanned anything.
- Keep a name in `ARCHITECTURE.md` or `CLAUDE.md` only while the tree has it, and declare it rather than discuss it — `Tests/HelmRuntimeTests/DocumentsNameTheTreeTests.swift` reads every backticked type, member, file name and file-and-line in the standing documents and fails on anything the tree lacks, including a path that moved and a line number past the end of its file, and it reads Swift with comments blanked (`Tests/Support/SwiftSource.swift`), so a name surviving only in a doc comment is a name the tree does not have.
- Put a name these documents carry *because* it was removed into that check's known-absent list with the reason, and a name macOS owns into its foreign list — anything else that fails the check means the backticks were the mistake. Never write a count of anything into prose — write the command that answers it, because a file count in a document was wrong three times in one day before it was deleted.
- Keep the standing documents beside `Package.swift` — the check looks for `ARCHITECTURE.md`, `CLAUDE.md` and `README.md` there and skips out loud when it finds none of them, which a failures-only summary reads as green.
- Reach anything outside the tree by its full path from a worktree — a worktree sits under `.claude/worktrees/`, inside the tree, so one level up from it is not where a sibling checkout is, and nothing links a worktree for you.
- Write an order here and a description in `ARCHITECTURE.md` — a sentence that tells you what to do and why belongs in this file, a sentence explaining how something is built belongs in that one, and holding the two genres apart is what stops either from being read twice.

## Shipping — what a person does, not a role

- Do not compose the text of a changelog entry in `Sources/HelmApp/ChangelogData.swift` — you make the code change, and what gets written for the person who updated is not the same act; read an entry that names a control against the running app rather than only for grammar, because the English string is the key, so a wrong name is faithfully translated into all seven other languages and the fix is one key deleted and rewritten in eight files.
- Bump the short version string in `Resources/HelmApp/Info.plist` for every release, and never edit the bundle version by hand — the updater compares versions and two releases sharing a number are invisible to every client, so no bump means no release; `Scripts/package-app.sh` sets the bundle version from the commit count into the assembled bundle, so a hand-written value in the tree is either ignored or a lie about which commit shipped.
- Reset the patch number on a minor bump and both on a major bump, and do not bump major while the version is in its zero series — a number that carries over from the previous lane stops meaning anything, minor is the lane, and the first major is reserved for a Developer ID plus notarization and a settled module set, which is what "ready for other people" means here.
- Declare a numbered line in full — which releases, in what order, where it ends — before its first release ships, or the patch number means nothing and any feature can be called a patch; name the line in one italic line under the first `CHANGELOG.md` section it ships and nowhere else, because a section there carries no other prose.
- Use `-dev` and no other prerelease suffix — the version comparison reads only the trailing number, so two different suffixes with the same number compare equal and the ordering silently stops working.
- Ship every release to the dev channel first as a prerelease, triage it against `~/Library/Logs/Helm/helm.log`, and publish the beta only at zero known problems — a dev build logs by itself and a beta build does not, so the dev round is the only round with evidence in it; publish the beta **without** the prerelease flag, because the Beta channel reads the latest-release endpoint and that endpoint skips every release marked prerelease.
- Push before creating the release, never after — the release is tagged against the remote HEAD, so an unpushed commit puts the tag on the wrong one.
- Attach both the disk image and the zip to every release, and put the digest line each of `Scripts/make-zip.sh` and `Scripts/make-dmg.sh` prints into the release notes — `Sources/HelmApp/Installer.swift` downloads the zip for the silent install and falls back to opening the release page without one, and since the updater strips quarantine from an ad-hoc signed bundle, `Sources/HelmRuntime/ReleaseDigest.swift` is the only check macOS does not do for us: without a matching line nothing installs.
- Write one `CHANGELOG.md` section and the same entries into `Sources/HelmApp/ChangelogData.swift` for every release — the file is the canonical English record and the app's list is what a person actually reads, and they have drifted about which versions exist before.
- Never delete or re-tag a release people may have downloaded — the updater requires a strictly greater version, so nothing can pull a user back; undo a bad dev build by publishing the next dev number with the reverted code and its digest lines.
- Say out loud that a prerelease user switching to Beta will see "up to date" — Beta reads the last non-prerelease tag, which is lower than what they are running, so the switch appears to do nothing until the next beta passes them; and do not read Dev answering "up to date" right after a beta ships as a fault, because Dev takes the newest entry in the whole list and until the next dev build exists that entry is the beta itself.
- Change `Scripts/dmg-settings.py` and `Scripts/design/make-dmg-background.swift` together — they hold the same slot coordinates seen from two sides, and only one of them draws.
- Judge a disk image by mounting it and never by reading the script — the script always finishes and always prints something that looks like a result; check that the mounted volume's Finder settings file is well over the size of an untouched one, which is the tell that Finder wrote a default and the settings were lost, that the volume carries the custom-icon flag, and that a strict signature verification still passes on the app *inside* the image.
- Check the window rectangle in `Scripts/dmg-settings.py` against the container window's own bounds and subtract the title bar, and never set the text size below the floor stated there — the value is the *window's* rectangle, so a window asked for the background's height alone simply does not show the bottom of the artwork and nothing errors, and the image builder writes an undersized text record happily before Finder rejects the whole settings file, giving no background, no positions and no complaint.
- Judge a new background against a composite of the real icons and their real labels, not against the empty artwork — Finder writes the item's name under the icon, and the first bezel ran straight through the word.
- Do not install over `/Applications/Helm.app` and expect the grants to survive — the signature is ad-hoc, so every build has a new cdhash and to TCC that is a different program; budget for re-granting Accessibility and Full Disk Access after each install, and do not read a passing strict signature verification as proof the grants held, because verifying says the bundle is valid and not that it is the same program TCC granted.
