# Three features for 0.8.0 — 2026-07-29

A welcome window that introduces the modules, a VPN spin that is a choice
rather than a fact, and two things the Duplicates list has been missing: a way
to select every extra at once, and Space to look at a file before binning it.

Decided with the user before any code:

- **The release is `0.8.0`, first built as `0.8.0-dev.1`.** The unreleased
  section is currently numbered 0.7.2 and holds Autopilot, a whole new module.
  VERSIONING.md says a new module is a MINOR bump, so the number the work
  already carries is the wrong one.
- **The welcome window tells, and does nothing else.** No module switches, no
  permission prompts. Both are real features and both belong to screens that
  already exist; an onboarding that also configures becomes a second place
  where module state lives, and the first thing anyone would have to debug is
  which of the two won.
- **It is shown once to everyone on 0.8.0**, not only to fresh installs. People
  upgrading have had Autopilot and Duplicates arrive without ever being told
  what they are.
- **The VPN spin is off by default.** This reverses a decision made in
  `2026-07-29-vpn-automation-feedback-design.md` — see below, where the reversal
  is argued rather than assumed.
- **Select-all means the extras**, one copy of everything survives. The module
  refuses to offer all copies of a group and that refusal is not being relaxed.

## 1. The welcome window

### Where the logic lives, and why not in `HelmApp`

There is no `HelmAppTests` target and there cannot easily be one: `HelmApp` is
the executable, and SwiftPM does not test an executable target without splitting
it. Every rule about this window that is worth a test therefore lives in
`HelmUI`, which has a test target, and `HelmApp` keeps only the `NSWindow` and
the SwiftUI hosting.

Two pure types, both in `Sources/HelmUI/Welcome/`:

```swift
/// Where the user is in the tour and what the buttons do there.
public struct WelcomeFlow: Equatable, Sendable {
    public let stepCount: Int
    public private(set) var step: Int
    public var canGoBack: Bool { step > 0 }
    public var isLastStep: Bool { step == stepCount - 1 }
    public mutating func next()
    public mutating func back()
}

/// Whether this installation has seen the tour.
public enum WelcomeGate {
    /// Bumped only when the tour itself is worth showing again.
    public static let revision = 1
    public static func shouldShow(seenRevision: Int) -> Bool
}
```

`shouldShow` compares against a stored `Int` that nobody has yet, so at 0.8.0
both a fresh install and an upgrade answer yes exactly once. The revision is a
number rather than a flag because the alternative — a `Bool` — makes "show it
again for the next big release" indistinguishable from a bug, and someone would
have to remember to clear it. Future tours bump `revision` deliberately or do
not run.

`next()` at the last step is a no-op rather than a close: closing is the
window's business, and a flow that can close itself cannot be asked what it
would do without a window.

### What each step says

Generated from `ModuleRegistry.all`. `moduleMetadata` already carries the
module's name, its SF Symbol and a one-line summary, each localized in all eight
languages by the module that owns it. **None of that text is written a second
time here.** A welcome window with its own copy of nine module descriptions is
nine descriptions that go stale on the first rename, and the descriptors are
where a module already says what it is.

Ten steps: one opening step that says what Helm is, then one per module in
registry order.

The only new strings are the chrome — the window title, the opening step's two
lines, and Back / Next / Skip / Done. All through `L()` with eight languages.

### The permission audit has to move

`PermissionAudit.run()` fires from `applicationDidFinishLaunching` and puts up an
`NSAlert` when macOS is withholding something. On a first launch that is the
same moment the welcome window wants, and two modal-feeling things arriving
together is not an introduction, it is a pile-up.

So: when `WelcomeGate.shouldShow` is true, the audit is deferred and run when
the window closes — by Skip, by Done, or by the close button, all three. When
the window is not shown the audit runs exactly where it does today. The audit
itself is not otherwise changed, and it keeps its own first-run wording.

### Keyboard and reach

Next carries `.defaultAction`, Escape maps to Skip, and Back is disabled rather
than hidden on the first step — a control that vanishes moves the two beside it,
and the third review pass already found one Done button with no default action
in Autopilot's preview. Every control is named: `NamedControlsTests` scans the
source and fails on an unnamed one, which is the only way this class of defect
is ever noticed by someone who is not locked out by it.

Step transitions use `HelmMotion` tokens. Reveals grow, they do not fade.

## 2. The VPN spin becomes a choice, and gets a colour

### Reversing the previous decision, with the cost stated

`2026-07-29-vpn-automation-feedback-design.md` says the animation always plays,
in all three notice modes, on the grounds that it is feedback that the app did
something rather than a notification. `VPNNotice`'s own doc comment says the
same. That reasoning is sound and it is being overruled deliberately, because
movement in the menu bar is the kind of thing a person is entitled to switch
off, and "it is good for you" is not an argument the app gets to make about its
own animation.

What the reversal costs is exact and belongs on screen rather than in this file:
with the spin off **and** the notice mode set to nothing, a rule that connects
or drops a tunnel produces no sign at all. That is a legitimate state for
someone who wants to be left alone, and it must be reachable only on purpose.
The note under the toggle says so.

### A separate field, because `tintToken` means something else

`StatusPlan.choose` ranks a countdown first, then a live spin, then **the first
module that carries a `tintToken`**, then the first that carries a title. A
tint is therefore a claim on the menu bar that outlives any one moment, and
`VPNDescriptor` records "no tint, ever" for precisely this reason: a second
tinting module makes "whose icon is this" a question settled by `ModuleOrder`,
which `StatusItemController` documents as latent only because no second module
tints today.

Colouring the spin must not spend that. `StatusAppearance` gains a field of its
own:

```swift
/// The colour of the spin, which is not a claim on the icon.
///
/// Deliberately not `tintToken`: that field is what `StatusPlan.choose` reads
/// to decide who owns the menu bar between moments, and a module that only
/// wants its own one-second animation coloured must not thereby become the
/// module that owns the icon all day.
public var spinTintToken: String?
```

`StatusItemController` passes `appearance.spinTintToken` to
`RingIcon.spinnerFrames`, falling back to the tint when it is nil so Keep
Awake's behaviour is unchanged. `StatusPlan.redrawKey` gains the spin tint: the
frame index already changes every tick so the key already differs, but a key
that omits an input is a key that will be wrong the first time someone caches
more aggressively.

### The three settings

| Key | Default | What it decides |
|---|---|---|
| `automationSpin` | `false` | Whether the ring turns when a rule fires |
| `spinTintConnected` | `green` | The colour when a rule raised a tunnel |
| `spinTintDisconnected` | `orange` | The colour when a tunnel went down |

`VPNAutomation.Kind` already distinguishes `.connected` from `.disconnected`, so
the mapping lands on a field that exists and no new model is needed.

`VPNDescriptor.statusAppearance` produces `spinUntil` only when `automationSpin`
is on, and sets `spinTintToken` from the firing's kind. Reduce Motion continues
to suppress the movement in `StatusPlan.spins`, which is a separate question
from the setting and stays where it is: the setting is a preference, Reduce
Motion is an instruction from the system.

### The swatch grid moves to `HelmUI`

The palette itself — `PaletteColor`, ten colours — is already shared. The grid
of tappable circles that chooses from it is a private method inside
`KeepAwakeSettingsPage`. VPN needs the same control, and CLAUDE.md's rule is
that shared plumbing moves rather than being written twice; the list of things
that were each written two or more times before they moved is in that file and
exists to stop this.

So `swatchGrid` becomes a component in `HelmUI/DesignSystem`, and Keep Awake
calls it instead of its own copy. The move carries the two facts its comment
already records and which are easy to lose: the swatches are `Button`s rather
than tap gestures, because a view whose only interaction is `onTapGesture` never
joins the key-view loop and Tab skipped every swatch; and the check mark inside
a light swatch is drawn dark.

## 3. Duplicates: select all the extras, and look before binning

### One rule, applied everywhere

`basketExtras(of:)` already encodes the whole policy — every path except the
first, and only where `UserFileScope.isRemovable` agrees. The new
`basketAllExtras()` is that method run across every group, not a second
implementation of the same idea. Anything else would let the two disagree, and
the one they would disagree about is which file survives.

The control says what it does. "Select all" is not the label: it invites exactly
the reading the module refuses, and a control that lies about its effect on
files is the failure this page is most exposed to.

**Paired with a clear.** A button that ticks three hundred checkboxes and offers
no way back except three hundred clicks is a trap, so it ships beside
`clearBasket()`, which empties the basket and trashes nothing — a different verb
from `emptyBasket()`, which is the one that deletes, and the two must not be
confusable in either the code or the labels. This is the one addition here that
the user did not ask for; it is included because the ask creates the need.

### Space, the way the Finder does it

A zero-size `Button` carrying `.keyboardShortcut(.space, modifiers: [])`, which
is the same device `DuplicatesView` already uses for Return → reveal in the
Finder, in the same overlay. It is disabled when nothing is selected, so Space
in an empty list does nothing rather than opening a panel onto no file.

`QLPreviewPanel` is AppKit and driven through the responder chain, so the panel
needs an owner: a small `NSViewRepresentable` in the view hierarchy that answers
`acceptsPreviewPanelControl` and acts as data source and delegate for the one
selected path. Pressing Space with the panel open closes it, which is what the
Finder does and what a person will try.

The action also appears in the row's context menu and in its
`.accessibilityActions`, beside Reveal. A keyboard shortcut with no visible
affordance cannot be discovered, and VoiceOver cannot reach a context menu
without a right-click — the same reasoning already written beside Reveal.

The testable part is thin and is extracted anyway:
`DuplicatePreview.target(selection:in:)` answers which URL a preview would show,
including the case where the selected path has just been trashed out from under
the list.

## What gets tested, and how

Pure logic first, with the test red before the code exists:

| Test | Pins |
|---|---|
| `WelcomeFlowTests` | Step bounds, Back disabled at the start, last step is Done, `next()` at the end does nothing |
| `WelcomeGateTests` | Shown at revision 0, not shown at 1, shown again after a bump |
| `WelcomeStepsTests` | One step per registered module, every step's text non-empty in all eight languages via `L(_:_:language:)` |
| `StatusPlanTests` (extended) | A module carrying only `spinTintToken` never wins the tint tier |
| `VPNStatusAppearanceTests` (extended) | Kind → token mapping; `automationSpin` off produces no `spinUntil` |
| `BasketAllExtrasTests` | Never baskets a group's first path; skips paths `UserFileScope` refuses; clear empties without trashing |
| `DuplicatePreviewTests` | Target for a selection, and nil once that path leaves the groups |

Language-parameterized rather than reading `AppLanguage.current`: the suite runs
in this machine's language, so a test gated on `.current` checks English eight
times. `L(_:_:language:)` exists for this and arrived in the unreleased work.

### What only a running build can answer

Four things, all verified through the env-gated screenshot harness in
`AppDelegate` and removed before committing — `grep -r HELM_DEBUG Sources/` must
be clean:

1. The welcome window on a defaults domain with no Helm keys, and the permission
   audit arriving **after** it rather than on top of it.
2. The two spin colours, judged by measuring frames rather than by watching.
3. Quick Look opening from an accessory app's settings window, which needs a key
   window and is the part most likely to simply not appear.
4. `HelmLog.memory` around the window and the panel: the spin's frame cache is
   claimed at about 1 MB for the first firing and nothing after, and a second
   set of cached frames per colour is a new claim on that number.

**The harness leaves nothing behind.** It drives real code, and real code
writes: the welcome revision key must be cleared from the defaults domain
afterwards, or the next launch is testing something that has already been seen.

## What this deliberately does not do

- **No general onboarding mechanism.** Modules do not contribute steps; the
  window reads their metadata. A module that wants a richer introduction is a
  second consumer and can argue for one then.
- **No spin for Autopilot**, which acts on its own far more often than VPN does.
  Same shape, same eventual want, still one module's problem until there are
  two.
- **Quick Look in the Disk list is not part of this.** It is the obvious next
  place and it is a different list with a different selection model.
- **The welcome window does not replace the changelog.** What is new in a
  release is what `ChangelogData` is for, and it already runs.

---

## Risks

- **Two modules now feed the menu bar in colour.** The spin tint is scoped so it
  cannot claim the icon, and `StatusPlanTests` pins that, but this is the second
  release in a row to touch the single status item and it is where a regression
  would be least visible. The countdown-versus-spin case is the one to watch by
  hand.
- **`QLPreviewPanel` in an `LSUIElement` app** is the least predictable piece
  here. If the panel will not take key focus from the settings window, the
  fallback is to open the preview as a sheet rather than to ship a Space key
  that sometimes does nothing.
- **The welcome window is shown to existing users**, which means it interrupts
  people who did not ask for it. It is once, Skip is always present and Escape
  works, and the revision key means a mistake here cannot repeat itself on the
  next launch.
