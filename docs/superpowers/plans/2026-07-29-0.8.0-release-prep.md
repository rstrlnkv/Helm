# 0.8.0 Release Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Renumber the unreleased work from 0.7.2 to 0.8.0 so the version matches what the release actually contains.

**Architecture:** Two files hold the number: `Resources/HelmApp/Info.plist` carries `CFBundleShortVersionString`, and `CHANGELOG.md` carries the section heading. `CFBundleVersion` is set from the git commit count by `Scripts/package-app.sh` and is never edited by hand.

**Tech Stack:** Swift 6, SwiftPM, plist, Markdown.

**Why:** The unreleased section holds Autopilot, a whole new module. VERSIONING.md: a new module is a MINOR bump. Shipping it as a PATCH would contradict the project's own rule.

**Independent of the three feature plans.** Do this whenever; the features do not depend on it and it does not depend on them. It must land before `0.8.0-dev.1` is cut.

---

### Task 1: Renumber the version

**Files:**
- Modify: `Resources/HelmApp/Info.plist`
- Modify: `CHANGELOG.md:8`

- [ ] **Step 1: Read the current value**

Run: `grep -A2 CFBundleShortVersionString Resources/HelmApp/Info.plist`
Expected: `<string>0.7.2-dev.35</string>`

- [ ] **Step 2: Set the new version**

In `Resources/HelmApp/Info.plist`, change the value under `CFBundleShortVersionString`:

```xml
	<key>CFBundleShortVersionString</key>
	<string>0.8.0-dev.1</string>
```

Do **not** touch `CFBundleVersion` on the next line — `Scripts/package-app.sh` writes it from the commit count.

- [ ] **Step 3: Renumber the changelog section**

`CHANGELOG.md` line 8 currently reads:

```markdown
## [Unreleased] — 0.7.2
```

Change it to:

```markdown
## [Unreleased] — 0.8.0
```

Leave every entry beneath it untouched. Nothing about the content changes; only the number it ships under.

- [ ] **Step 4: Verify no other file claims 0.7.2**

Run: `grep -rn "0\.7\.2" --include="*.swift" --include="*.plist" --include="*.md" --include="*.sh" . | grep -v CHANGELOG.md | grep -v docs/`
Expected: no output. (`CHANGELOG.md`'s older `[0.7.1]` sections and the `docs/` specs mention past versions legitimately and are excluded.)

If this prints anything, the version is spelled in a third place and that place has to be found before a release — the updater compares versions, and two files disagreeing is how a build ships announcing the wrong one.

- [ ] **Step 5: Run the suite**

Run: `swift test`
Expected: 1575 tests, 0 failures, 8 skipped. The version is not asserted anywhere, so this is a "nothing else moved" check.

- [ ] **Step 6: Commit**

```bash
git add Resources/HelmApp/Info.plist CHANGELOG.md
git commit -m "release: the unreleased work is 0.8.0, not 0.7.2

It holds Autopilot, which is a new module, and VERSIONING.md says a new
module is a MINOR bump. The number the work carried was the wrong one.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>"
```
