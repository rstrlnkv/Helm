# Launchpad

`Sources/Modules/Launchpad/` is an app launcher: what is installed, how the person arranged it, what they hid. The engine (`Sources/Modules/Launchpad/Engine/`) reads, edits and launches; the UI (`Sources/Modules/Launchpad/UI/`) is a full-screen window the person opens with a shortcut they record, and a settings page, registered in `Sources/HelmApp/ModuleRegistry.swift` (`LaunchpadDescriptor`). The reasons live on the doc comments of the code that carries them:

- an app is its bundle id and nothing else is stored; a path belongs to the latest catalog read, so a planted layout file cannot make Helm launch a path: `Sources/Modules/Launchpad/Engine/Logic/LaunchpadLayout.swift`;
- the three roots, the walk judged by name and one `lstat`, the duplicate rule, why Safari is no fourth root, and the capped reader for files out of a bundle: `Sources/Modules/Launchpad/Engine/SystemPorts.swift` (`FileSystemAppCatalog`, `cappedRead`);
- a read that was not `complete` drops nothing, and a read never writes: `Sources/Modules/Launchpad/Engine/Logic/LaunchpadReconcile.swift`, `Sources/Modules/Launchpad/Engine/LaunchpadEngine.swift`;
- a tile says its name in `.help`; a name that cannot break shrinks to `LaunchpadMetrics.unbreakableShrink` rather than split mid-word, and a cut one scrolls on hover. A place to break is a space, a hyphen, a soft hyphen (U+00AD: the built German and Portuguese names carry them and break there) or a Han, Hiragana, Katakana or Hangul letter (`LaunchpadLabel.canBreak`): `Sources/Modules/Launchpad/UI/LaunchpadTiles.swift`, `Sources/Modules/Launchpad/UI/LaunchpadGeometry.swift`;
- the window measures nothing: sizes come from the screen and the grid settings (again only when those change: `regrid`), pages are placed by offset, icons are its own cache: `LaunchpadScreen.swift`, `LaunchpadIcons.swift`, `TheLaunchpadWindowMeasuresNothingTests`;
- where each tile sits is one pure function, first fit in reading order (a small tile a cell, a large folder a block of 2×2); drawing, paging, hit test, the lift's gap and the arrow keys all take their cells from it: `Sources/Modules/Launchpad/UI/LaunchpadPlacement.swift`;
- the layout file is private, bounded, and a bad one is moved aside once before the first save: `Sources/Modules/Launchpad/Engine/LayoutStore.swift`, `Sources/Modules/Launchpad/Engine/Logic/LayoutCoding.swift`, `Sources/Modules/Launchpad/Engine/Logic/LaunchpadLimits.swift`.

## The catalog and the layout

`AppCatalogPort.read()` is pull-only; `observeChanges` tells the model when to ask (`CatalogChange.concerns`). A root that will not open, or a walk stopped at the ceiling, makes `CatalogReading.complete` false. The layout is saved only on a person's edit (`LaunchpadEngine.apply`), through one lock over read, reconcile, edit and save; only the latest catalog read is kept.

**Drops are edits by anchor.** A drop lands by anchor: an edit names where an item goes by the id of the item beside it, never by an index, because the window draws a subset of `layout.items` (`LaunchpadEdit`, `LaunchpadLayout.edit(dropping:source:destination:folderName:)`; a folder never nests; a drop that changes nothing is nil). **A page break is an item**, `.pageBreak`, stored as `{"pageBreak": true}` in the same list: it stays where it is when its neighbour moves away, `normalized()` keeps one only between two items and at most `LaunchpadLimits.maxPages - 1`, and the file's version stays 1.

**Folder names** are Helm's own words, copied from two macOS tables (the iPhone's `FolderNaming.loctable` in FrontBoard, and for the six categories it lacks the `public.app-category.*` descriptions in CoreTypes' `InfoPlist.loctable`) and never read from them at run time: private files in a layout nobody promised. `Sources/Modules/Launchpad/UI/LaunchpadCategoryName.swift` maps the 28 category ids to catalog words (every `*-games` subtype is Games; a new folder takes the target's category, else the dropped app's, else `categoryOther`, "Others", plural and Helm's own). Utilities and Video are the kit's words since the host and Autopilot draw them too (Architecture/Localization.md § Words two parts draw). Healthcare & Fitness keeps CoreTypes' English because "Health" is Homebrew's (`OneEntryPerKeyTests`).

**A folder's size is the folder's.** `Folder.large` is stored as `"large": true` inside the folder's own entry, only when set, so the version stays 1 (an older build ignores the key and drops it at its next save); anything under it but `true` reads as small. The edit `.resize(folder, large:)` is refused when it changes nothing, so a stale menu writes nothing; every edit that keeps the folder keeps the flag. Reset arrangement builds new folders, all small (`ALargeFolderSizeIsWrittenOnlyOnAFolderAndNeverLostTests`).

**A moved app.** `LaunchpadLayout.categoryOverrides` (beside `hidden`) holds apps the person sent to another category, stored as `"moved": {"<bundle id>": "<category slug or others>"}` only when there is one (version 1). The value is a `LaunchpadCategoryTarget`, not a block's `Kind`, which also has Recently Added. `LayoutCoding.swift` reads it leniently; `normalized()` bounds it again and **carries it, which is the whole reason Reset arrangement keeps it** (a move is not an arrangement of the grid). The edits are `.setCategory(app, target)` and `.returnAllToOwnCategory`, each refused when it changes nothing; the engine's `resolved` turns a move to the app's own category into "take the move away". `reconciled` drops the move of an app a **complete** read does not find (like `hidden`), never on an incomplete one.

**The date added.** `CatalogApp.added` is the date Finder shows as "Date Added" (`ATTR_CMN_ADDEDTIME`), because a copy keeps the creation date and a freshly dragged-in old build would not read as new. It is nil, and the app never "recent", for an app in `/System/Applications` (a macOS update adds them all again), a symlinked bundle (the date would be the link's) and a value that would not read. One `getattrlist` per app, not `URLResourceValues`, which costs more memory. An app updated in place shows as recent for 30 days.

A hidden app leaves its folder. The module is not a `BackgroundScanning` module, and the layout is not a sealed setting: it names no path.

## The default arrangement

What a person sees with no arrangement of their own: `LaunchpadLayout.defaultArrangement(for:utilitiesFolderName:)` in `Sources/Modules/Launchpad/Engine/Logic/LaunchpadDefaultArrangement.swift`: Apple's apps in the Dock's order, one folder of the system utilities, a page break, then every other app A–Z. It is used in two places only, both in `LaunchpadEngine`: a read or an edit with **no layout file** (`LayoutRead.absent`; the first edit saves what the person was shown, hidden apps aside), and `.resetArrangement`, which keeps `hidden` and the moves. A stored layout is never rearranged by it; new apps go to the end, as `reconciled` always puts them.

Apps are told by bundle id, never by name. The lists are literals copied at build time from the Dock's default property list and `/System/Applications/Utilities` (plus Automator, Font Book, Image Capture, Time Machine), never read at run time. Any app under that folder is also a utility, so one a later macOS adds lands in the folder; a folder of fewer than two members dissolves (`normalized()`). The folder's id is one fixed literal, so an open folder survives the default being built again. Its name is `HelmWord.utilities`, passed as a closure (`LaunchpadEngine.init(utilitiesFolderName:)`) and asked each time, so a language change shows; the engine holds no strings.

## How Launchpad's model reaches its engine

`LaunchpadViewModel` (`Sources/Modules/Launchpad/UI/LaunchpadViewModel.swift`) is built with the engine by the descriptor's `makeModule`. It reaches the engine only through `read`, `hide`, `unhide`, `resetArrangement`, `launch`, `observeChanges`, and `LaunchpadEdit`s through `apply`. Every blocking call hops off the main actor, and its answer is dropped when a newer request exists or the model was stopped.

A launch is resolved in the engine: `launch(id)` reads the catalog afresh, finds the id, asks the bundle at that fresh path for its id and only then hands the URL to `AppLauncherPort` (`Sources/Modules/Launchpad/Engine/Logic/LaunchResolution.swift`); a path never comes from the layout file or the last snapshot. `SystemAppLauncher` is the only code that opens an app. **The count is recorded after a successful open**, in `LaunchpadEngine.launch` and nowhere else.

The model starts nothing in `init`. The settings page's `.task` and the window each call `whileShown()`, which subscribes to the catalog watch before its first read, so no change falls between the two. Each caller is a watcher of its own: the snapshot and notice are dropped when the last leaves, so a closed window holds no list of apps. Only the oldest watcher reads for a change; a launch refreshes only when a watcher other than the window's is there. `TheCatalogIsReadOnlyForWhatNobodyHasAlreadyReadTests` counts the reads.

## The window

The model is the one door: `showLaunchpad()` and `toggleLaunchpad()` open the window or bring the open one forward, `closeLaunchpad()` and `stop()` close it; `present`, set by the descriptor, builds it, and a model without it (a test) opens nothing (`LaunchpadWindowHandle`). The shortcut is the descriptor's `LaunchpadHotkey` slot, with no default.

`LaunchpadWindow` (`Sources/Modules/Launchpad/UI/LaunchpadWindow.swift`) is a borderless non-activating panel over the screen the pointer is on, not a `HostWindow`: Helm stays an accessory, with no Dock icon and no Space pulled. It is built when asked for, with its own `LaunchpadScreenState` and icons, and releases all of it when it closes: on Esc (order: § Edit mode), a click on the empty background, an app that opened, the panel losing key or another app coming forward (neither while the Hidden prompt is up), the Space or screens changing, the model stopping and the shortcut's second press.

**How much of it shows has one writer**, `LaunchpadWindow.apply`: the panel's alpha and `state.reveal` (`LaunchpadReveal`), driven by the fingers' progress during a scrub and a settle's own clock after it. It closes by a settle to 0 with keys swallowed and the mouse ignored, so a click goes through. Reduce Motion cuts the settle and turns the zoom, pop and glow off. The glow (`LaunchpadGlow.metal`) needs the Xcode MetalToolchain component; a failed compile falls back to the plain wash.

**Lifetime.** What SwiftUI's hover and context-menu responders keep after the window is gone must not reach the window's state: every closure the screen gives a tile holds `state` weakly (`LaunchpadScreen`), and `finish()` empties the icon cache (`AClosedLaunchpadWindowLeavesNothingOfItselfBehindTests`).

A trackpad swipe drags the page and settles it on release (`LaunchpadSwipe`, pure); the drag publishes only `LaunchpadPageDrag.offset`, never the state. **An open folder's card has pages of its own** (`(columns - 1) × (rows - 1)` apps, `LaunchpadSurface.Card.capacity`), turned by the same gestures through `state.cardPage`, `state.cardDrag` and a second `LaunchpadSwipe` (`cardSwipe`, so the two never share their travel). A card's tiles are addressed by their index in the folder's whole list. The Apps/Categories switch is the kit's `HelmHeaderTabs` on the search row, drawn only when `LaunchpadGeometry.switchFits` says the window leaves it `LaunchpadMetrics.switchRoom`; § The category view.

**Large folders.** **A page holds `capacity` cells, not `capacity` tiles**: `LaunchpadPaging.pages` cuts the list at each page break and then by what `LaunchpadPlacement.place` fits; a page is still a run of the stored order and its first tile always fits. A large folder shows its first nine apps three by three; with more, the ninth cell is four tiny icons and opens the folder. The inner icons are plain images, not buttons, because the panel takes the press before a button sees it: `LaunchpadScreenState` resolves a click from the press's point (`LaunchpadHit.icon(at:block:mark:edge:iconTop:apps:)`, from the same `LaunchpadFolderMark.frame(ofIcon:size:edge:)` the mark is drawn by); an icon launches that app, anywhere else opens the folder.

**The system's dialog.** While the Hidden block's prompt is up (`LaunchpadWindow.promptChanged`), resign-key and another app's activation end nothing and the panel takes no mouse and swallows keys (`LaunchpadPanel.isPrompting`); Space and screen changes still close the window.

### The icons

The window never draws an icon on main. `LaunchpadIcons` (`Sources/Modules/Launchpad/UI/LaunchpadIcons.swift`) answers `image(for:side:)` and nothing else: a hit is a one-representation `NSImage`, a miss asks a private bounded `OperationQueue` (`offTheCooperativePool` is unbounded) to draw it with `LaunchpadIconRender` and answers meanwhile the largest image the path has had, or an empty slot. The reason: the system renders one more bitmap per path for every distinct size asked, on main, in the middle of a body.

- The cache is bounded by `LaunchpadIcons.limits` and soft where it must be: an arrival evicts only an entry not asked since the last `onArrival`.
- **A result may not outlive its asker.** `generation` is bumped by `removeAll` and `reconfigure`; an operation checks it before and after drawing and the arrival block on main reads it again (payload captured before the hop, reading taken inside it).
- **The first snapshot waits for page 0's icons** (`LaunchpadScreenState.update(snapshot:)`) until they are drawn or `firstIconsDeadline`, whichever is first; a late icon shows empty and arrives by `onArrival`.

### Show in Finder, Copy Path and the new dot

**Show in Finder and Copy Path** are two rows of an app's context menu (`LaunchpadMenu`) and two VoiceOver actions, for apps and never folders. Copy puts the path on the pasteboard as text only, except that a copy of a hidden app also carries `org.nspasteboard.ConcealedType` and `TransientType` (`LaunchpadPasteboard`, a board by name, so `ACopiedPathOfAHiddenAppIsMarkedConcealedTests` never touches the general one). Whether a clipboard manager honours the markers was not measured, and a copied path stays on the pasteboard after the card locks. The model's `revealApp` and `copyPath` default to nothing,so a test never reaches Finder.

**A hidden app's path is offered only by the open, unlocked Hidden card:** `LaunchpadScreenState.fileActions(for:)` is the one maker, and **the same judgement (`filed(_:)`) runs when the menu is built and again at every press** against the current snapshot, so a press after the card locked or the app moved does nothing or hands the current path, never the one captured at build (`AHiddenAppsFileIsOfferedOnlyByTheUnlockedHiddenCardTests`, `AFileActionActsOnlyWhileItsOfferStandsTests`, `AFileActionNamesThePathTheCatalogHoldsNowTests`).

**The new dot** is the system blue (`newDotInk`, the module's own: `HelmSignal` has no blue) on an app that `LaunchpadCategories.isNew` says is new: added within `recentDays` and with no launch in `snapshot.launchCounts`. Nothing is stored for it; none is on a folder. "New" counts only launches made from Helm: a launch from the Dock or Finder does not clear the dot.

### The grid settings

The Grid section is six plain keys in the module's store (`LaunchpadGridSettings`; deployed data, the names never move): `grid.automatic`, `grid.rows`, `grid.columns`, `grid.iconSize`, `grid.showNames`, `grid.sizeMultiplier`. They are **not sealed**: sealing is for settings that steer unattended work (`Architecture/StoredSettings.md`); these choose a grid with the person present and a forged value only picks a number inside the ranges. The model reads them in `init`, in `showLaunchpad()` and when the page appears, never per frame.

`LaunchpadGeometry.make(for:topSafe:settings:)` is pure. **Automatic** is seven columns by five rows on every screen, scaled to the screen (§ The grid scales to the screen); **manual** takes the stored counts at scale 1, to what the screen holds (a cell is square, so a narrow screen holds fewer columns than asked). The icon asked for is a ceiling: a grid that does not fit shrinks it to no less than `iconFloor`. **Show app names** (default on) leaves out the name under an app's icon; `.help` and VoiceOver keep every name. **Two places keep names with the setting off:** the unlocked Hidden card, and **the Categories view** (`pairedColumns`: two cells to a block, names on, columns rounded down to even; the state keeps both geometries and a search uses the grid's own).

A changed grid reaches an open window through the model's published `grid` and `LaunchpadScreenState.regrid`: it cancels a lift (a cell address is `page * capacity + slot` and means nothing in another capacity), makes the geometry again, tells the icon cache and cuts the same order into pages again. **A changed grid re-pages and writes nothing** (`ARegridRepagesAndWritesNothingTests`); stored page breaks stay.

### The grid scales to the screen

Under Automatic the grid is `LaunchpadMetrics.automaticColumns` by `automaticRows` (7 by 5; the category view's paired grid 6 by 5) on every screen, and what changes is how big it is drawn: `LaunchpadMetrics.scale(for:topSafe:)`, `s = clamp(min(W / 1440, (H - topSafe - 36) / 864), 0.6, 1.6)`, pure and finite for any input (`AutomaticIsTheSameGridOnEveryScreenTests`). **Manual is drawn at scale 1.**

- **The scale** carries gaps, padding, the cell's chrome, the label's font, the search field's top, the dots' room (`LaunchpadGeometry.dotsRoom(scale:)`) and the card's padding. **The pitch is square**: a cell is as wide as it is high; the icon is the least of what was asked and what the width and height leave.
- **The multiplier** (`grid.sizeMultiplier`, "Overall size"; its own key, since `grid.iconSize` is points) multiplies **the scale**. **Above 1 it is held** (`LaunchpadGeometry.automaticScale`): chrome grows with the scale as fast as the icon, so on a screen that 7 x 5 at x1 nearly fills, an unheld x1.25 drew a smaller icon than x1; the scale is the largest at which seven by five still fit, never less than `s`.
- **Fewer than 7 by 5** only where the screen cannot hold them at the floor icon (`LaunchpadGeometry.counts`); no width rule drops columns for a label.
- **A large block's well meets the visible bodies of the four icons it stands for**: its inset is a small icon's (`LaunchpadGeometry.largeEdge`). One function, `LaunchpadFolderMark.inset(_:edge:)`, is read by the drawing (`LaunchpadFolderMark`, `LaunchpadCategoryMark`, `LaunchpadHiddenMark`) and by hit testing (`LaunchpadHit.icon`, `categoryIcon`).

**The header row has one rule.** The search field's top is `topSafe + 28 * s`, the tabs sit on the same row and begin at the left edge of the grid shown (`LaunchpadGeometry.sideInset`). `topSafe` is the taller of the screen's notch room and its menu bar (`LaunchpadWindow.topSafe(safeTop:frame:visible:)`). `gridTop`, which hit tests, the card's origin, the lift and the dots read, is the grid's start plus half of the room the rows leave.

### A cut name scrolls on hover

`LaunchpadLabel.overflow(name:room:scale:oneLine:)` is the one place that says whether a name is cut (0 where the whole name is drawn, else the distance the shrunk one-line name must move to show its end). While the pointer is on a cut tile, and not pressed or under Reduce Motion, a clipped one-line `Text` scrolls by `HelmMotion.marquee(distance:)`; `.help` names the app whole. Nothing measures a view.

### Lifting a tile

A tile is lifted with raw mouse events, not SwiftUI's drag and drop (the source folder bans those words, `TheLaunchpadWindowMeasuresNothingTests`). `LaunchpadPanel.handle` swallows a press only when it began on a tile and a lift is allowed (`liftAllowed`: the grid shown, no search text, no name being typed, no launch under way). A press let go without moving is a click **unless it was held `editHold`, which began the edit mode and is no click** (§ Edit mode). No lift in the category view (`beginLift` refuses).

`LaunchpadLift` (pure, `Sources/Modules/Launchpad/UI/LaunchpadLift.swift`) is the machine: `feed` returns **one** effect naming **cell addresses** (`page * capacity + slot`, a tile's index, because a large block covers four cells); `LaunchpadHit.at` finds what is under a point from `LaunchpadGeometry` and `LaunchpadSurface.slots` alone; the numbers are `LaunchpadLiftTiming`. **The pointer over the gap itself changes nothing**, and the gap goes only by dwell, so a hundred moves inside a cell publish nothing. The pointer's place is `liftPoint`, read only by the overlay; `stuckWake` finds a mouse-up that never came. The gap's id is `LaunchpadEntry.gapID`, a leading space no bundle id can spell. A release maps to a drop by anchors (`.beside`, `.onto`, `.newPage`), `LaunchpadLayout.edit` makes the edit or nil, the page shows the result at once and `LaunchpadViewModel.place` writes it. Nothing is written on Esc, an abort, the window closing, a search typed, or the carried app vanishing from a new snapshot.

**Folders in the lift.** A folder tile is a target twice: held on its icon it is armed (a release adds the app), held longer its card opens (only for a carried app: folders never nest) and the same machine goes on against the card. **A card with pages turns them at its sides**, never past its first or last page, and a turn moves the gap onto the page shown (`seatGap`). The card closes after the pointer has been **outside for `leaveCard` and only once it has been inside**: a card opens at the window's middle, not under the pointer, and without that rule it would close at once and open again. A release anywhere but inside the card closes it first and is a drop on the grid. **The gap is as big as the tile carried** (`publishPages`), because a large block's landing place depends on its neighbours (`ADropLandsWhereTheGapShowedTests`).

**The name.** The card's title is a `TextField` bound to `state.nameDraft`; while `state.renaming` is true `LaunchpadPanel.handle` asks `state.handleNameKey` first: Return commits (trimmed, written through `LaunchpadViewModel.rename` only when changed; blank reverts), Esc reverts and leaves the folder open, **every other key returns false** so caret, arrows and typing are the field's. A folder just made opens with the field focused and selected.

**Reordering by key and by VoiceOver.** The same drop with no pointer: Option+arrow moves the chosen tile, Option+Shift+arrow combines it toward that neighbour (an app onto an app makes a folder) or, in an open card, takes the app out; each chord is one written edit and a plain move never makes a folder. `LaunchpadKeyMove` (pure) turns the drawn order into a `LaunchpadDropDestination` by anchors, never an index of the layout, and `LaunchpadScreenState.reorder(tile:_:)` writes through `LaunchpadLayout.edit(dropping:)` and `place`: no engine code and no `.move(toIndex:)`. **Across a stored page break** the tile lands on the near side of the page it enters and the break stays. **A folder never nests**: `combine` refuses a carried folder in the pure type. A key during a write is dropped, not queued. VoiceOver gets the same moves as custom actions. `AKeyOrAnActionMovesATileAsTheDropWouldAndLosesNothingTests` pins the chords.

### Edit mode

The mode where tiles are arranged and apps are removed. **Begins** by a press that stays `LaunchpadLiftTiming.editHold` on a tile without a lift, or by "Edit" (`HelmWord.edit`) in a menu; **ends** by Done, Esc, a click on the background (an open folder closes first), a search typed, the category view, and the window going (`shutdown`). `editAllowed` is `liftAllowed` outside the category view and the Hidden card. The Esc order: the removal's card, a lift, the name field, an open folder, the edit mode, the search, the window.

`Phase.held` in `LaunchpadLift` follows `pressed` once the hold has passed and its effect is `beginEditing(address:)`; from `held` a move lifts the tile (a long press then a drag is one gesture) and a release is no click. In the mode a click on an app launches nothing (`openApp(_:_:)` is the one door), a folder opens, and the new-app dot is not drawn. `removable` is the apps the Uninstaller itself offers (`onVerdicts`), asked once when the mode begins and again only when the (id, path) pairs change; no answer is an empty set.

**Badges** (`LaunchpadBadge`, pure): an eye (hide) on every app tile, a × on a tile whose app is in `removable`; none on a folder. `frames(_:cell:icon:iconTop:)` is the one function the tile draws by and `LaunchpadHit.badge(at:in:)` tests by; the press frame is **held inside the cell** (at scale 0.6 it would reach over the row above), and a press on a badge makes `pointerDown` answer false, so the panel passes it to the SwiftUI button. **The wiggle** is on the mark only (`HelmMotion.wiggle(seed:)`, the seed a stable hash of the tile's id, not `hashValue`, which changes at each launch); **under Reduce Motion there is none**, the badges alone say the mode is on. **Done** sits on the search row when the window leaves it `LaunchpadMetrics.doneRoom` (`doneFits`), else above the page dots.

**Removal.** The × press is `askToRemove(_:)`: for an app in `removable` it asks the model (`previewRemoval`), and the answer raises a modal card (`.asking`, which takes no press for `removalDwell`, so a click aimed at the × does not land on its button) with `HelmConfirm.trash`, Cancel and Move to Trash (or `quitAndMoveToTrash` when the app is open). **No hidden app is offered, asked about or asked to be removed.** **Only the card's button removes**: the card keeps the candidate (id, path, name) it counted, a snapshot that holds the app otherwise closes the card (`keepTheCardHonest`), and `confirmRemoval()` re-checks the same; the consent to quit is the card's `running` and never more, since the engine refuses an app that started after the card. `removeApp` on the model owns the removal from there: **it lands even if the window closes**, says how it went by a `LaunchNotice` only while a watcher remains, and logs the outcome and counts only, never a name, an id or a path.

## The category view

The person chooses Apps or Categories by the switch in the window; the choice is a plain key `view.mode` ("apps" or "categories"; anything else reads as apps), **not sealed** (it steers nothing unattended), read in the model's `init` and in `openWindow()`, never in a SwiftUI initial value, and written through `setViewMode`: `Sources/Modules/Launchpad/UI/LaunchpadViewMode.swift`.

**A block is a folder-shaped entry.** `LaunchpadCategories.blocks` (pure, `Sources/Modules/Launchpad/Engine/Logic/LaunchpadCategories.swift`) turns the visible apps, counts and clock into blocks; the state holds each as `.folder(id:name:apps:large: true)` with `categoriesShown` set, so placement, paging, hit test and card are the large folder's. Each block's id is fixed and the same in every language, because `reflow` reopens an open card by id. What keeps a block from being a folder is the mode: no lift, rename, resize or `onPlace` call. Hide in the block card's menu does write the hidden list, as the owner chose.

**What is in a block and in what order.** An app is in the block of its `public.app-category.*` value; an unknown value goes to Others, empty blocks are omitted, a hidden app is in none. "Recently Added" is first and only when it has an app: added within 30 days (`recentDays`; a future or missing date is not recent), newest first, and it stays in its own category too. The other blocks go by the total of their apps' launches, most first, ties by localized name, then kind; Others is last. Up to four apps draw as large icons; from five, three are large and the fourth cell is a cluster of tiny icons that opens the card.

**Move to category.** Every app's context menu (`LaunchpadMenu`: Hide, and the submenu "Move to category") has the app's own category as an undo row on top and the 28 categories in the person's language with "Others" last (`LaunchpadCategoryName.choices`, not cached, the language can change). It is on the grid's tiles, on card tiles, and by right-click on a category block's large icons; not on a large folder's mini icons, nor on a control-click, which is a left press in this panel. Move is not a VoiceOver action (an action cannot be a submenu); a category block's large icons have no Hide action, so VoiceOver reaches those apps through the block's card. `move(_:to:)` arms the reorder curve in the category view only and only when the request changes the state's own record, since a refused one would leave the flag unspent.

**The counts file.** The launch counts sit beside the layout in its private folder (version 1, a count for each bundle id, bounded by `LaunchpadLimits`). An unreadable file reads as no counts (the window never breaks) with one warning and no id in it; the first `record` or reset moves it aside once to `.unreadable`. A read never writes. One lock covers read, bump and save, and the engine's lock comes before it. `resetLaunchCounts` (the page's "Reset launch counts", no dialog: counts cost nothing to relearn) writes the empty document.

## The Hidden block

In the category view the last block is "Hidden", drawn as a lock with no icons and no count (`LaunchpadHiddenMark`). It is not a `LaunchpadCategoryBlock.Kind`: a hidden app never enters the engine's blocks. `reflow` appends a UI entry with the fixed id `LaunchpadHiddenBlock.id` and `apps: []` always, so while locked no hidden name is in `segments`, `top`, `pages` or the icon cache; names exist only in `folderApps` and `cardEntries` of the open, unlocked card, read from `LaunchpadSnapshot.hiddenApps`. A hidden app is in no search and no log line.

**The lock** is `LaunchpadHiddenGate` (`Sources/Modules/Launchpad/UI/LaunchpadHiddenGate.swift`): `locked`, `asking`, `unlocked`, in memory only, one gate for each window state and each settings page. It asks a `LaunchpadAuthPort` (`Sources/Modules/Launchpad/Engine/Ports.swift`, whose doc comment names which reasons fold into each answer); `SystemLaunchpadAuth` (`SystemPorts.swift`, the one file that imports LocalAuthentication) asks `deviceOwnerAuthentication` with reuse duration 0, so the system draws the dialog and Helm never sees a password; a test process answers `.unavailable`. Only `.success` unlocks. Each ask carries a ticket that `lock()` bumps, so an answer after a lock, a close or a newer ask is dropped.

**What closes it.** `open(folder:)` is the one way in. `closeFolderQuietly()` locks when the open card is the Hidden one; `shutdown()` locks and closes it; the gate locks by itself after 90 s of an unanswered prompt, and the settings page locks in `onDisappear`. In the card the menu offers Show (`unhide`), Show in Finder and Copy Path (the only place a hidden app's path is offered) and no Move. The gate is a UI-level guard (`LaunchpadViewModel.launch` and `unhide` are not gated). It is not encryption: `layout.json` still names the hidden ids and Finder and Spotlight still find the apps.

## The Dock icon

Helm has no Dock icon, so Launchpad's is a second, tiny app nested in the bundle: `Helm.app/Contents/Helpers/Helm Launchpad.app` (Helm Dev: `Helm Dev Launchpad.app`), the target `HelmLaunchpadHelper` (`Sources/HelmLaunchpadHelper/main.swift`). The person drags its icon from the settings page to the Dock. A click starts the helper, which opens `helm-launchpad://toggle` at the Helm it sits in, without activating it, and quits. **Its shown name is the word for "Apps" in each language** (`Resources/HelmLaunchpadHelper/<lang>.lproj/InfoPlist.strings`, copied in by `package-app.sh`), the words macOS's own Applications folder shows, except ru, the owner's word "Приложения" (macOS says "Программы"); The panel's "another app came forward" ender ignores the helper by bundle id (`LaunchpadWindowEnders`), and the click closes the window by toggling it.

**The link is input from outside the process**, so `LaunchpadLink.accepts` (`Sources/HelmRuntime/LaunchpadLink.swift`) compares the spelling `URL` gives back with `<scheme>://toggle`: `URL(string:)` drops invisible host characters (U+200B, U+00AD, the byte-order mark), so a link that reads as the exact one after that is accepted, and the result is still only the toggle; any other scheme, host, path, query, fragment, user or port is refused, and `ModuleHost.openLaunchpadFromLink` logs one throttled `link refused` line without the URL. Links closer than 0.5 s to the last accepted one are dropped. An accepted link presses the descriptor's own shortcut action, so the Dock and the shortcut cannot disagree; with the module off it posts `.helmOpenSettings` for the Launchpad page.

**One helper per channel.** The release helper's bundle id is `com.helm.app.launchpad` and its scheme `helm-launchpad`; Helm Dev's are `com.helm.app.dev.launchpad` and `helm-dev-launchpad` (`AppBuild`). The helper's plist (`Resources/HelmLaunchpadHelper/Info.plist`) names its parent and its link; the parent is the bundle three levels up when its id matches, else the app LaunchServices knows by that id, so a Helm Dev link never wakes the release. Helm writes no Dock setting: a pin is the person's own, and a stale pin when Helm moves is fixed by dragging the icon again.

**The panel sits just below the Dock.** The window's level is `CGWindowLevelForKey(.dockWindow) - 1` (`LaunchpadWindow.level`): above every ordinary window, under the Dock, so the Dock draws over the panel and the pinned icon stays clickable, as with macOS's own Launchpad. The frame is the whole screen, and the menu bar draws over the top strip.

**A limit: over a full-screen app the Dock stays hidden.** Over a native full-screen app (its own Space) the Dock is not drawn when the panel opens, because a full-screen Space hides it. Helm cannot show it from there: `NSApp.presentationOptions` can only hide the Dock more, activating Helm with it set to `[]` left it hidden, warping the pointer to the bottom edge did not bring it, and no public or transient private call that reveals it was found; the calls that would persist (writing `com.apple.dock`, restarting the Dock) change the person's own setting, so they are not used. The owner left it so.

## The trackpad pinch

Four or five fingers brought together **scrub the window open**, spread they **scrub it shut**; letting go completes the gesture at the midpoint or on a quick flick and otherwise puts it back (`LaunchpadViewModel.pinched(_:)`; a pinch with the window open brings it forward, a spread with none open does nothing). **Off by default**: a plain key `gesture.pinch` (`LaunchpadPinchKey`, deployed data), not sealed, since it steers nothing unattended.

**The route.** The fingers come from MultitouchSupport, a private framework with no header, behind `TrackpadTouchPort` (`Sources/Modules/Launchpad/Engine/Ports.swift`). `MultitouchSupportPort` (`SystemPorts.swift`) `dlopen`s it and `dlsym`s five symbols, as `DisplayCorners` does, so a macOS that moved it is `.frameworkMissing`, never a crash. A tap or global monitor was ruled out: an event carries no finger count. Helm declares no permission for it (`permissions: []`); this is read from other projects' notes and was not tried against a denied Mac.

**The layout is not trusted.** Every frame goes through `TouchFrame.init?` (`Sources/Modules/Launchpad/Engine/Logic/TouchFrame.swift`), which refuses an out-of-range count before any record is read and any non-number or out-of-range position, state or time. `FrameTrust` counts refusals in a row; at 30 the port drops every frame and the engine says `layoutRefused` once and stops the watch.

**The recognizer** (`Sources/Modules/Launchpad/Engine/Logic/PinchRecognizer.swift`) is a value fed frames of one pad; `feed` answers `began`, `moved`, `ended(complete or revert)` or nothing. A scrub begins only when the spread change beats the centroid's travel by `swipeShare` (a swipe moves the centre more than it changes the spread), and a swipe, a backwards pad clock and a scrub past its limit revert. **Every number sits in `PinchThresholds` and is an untuned guess**; the engine keeps one recognizer per pad, so two pads are never one hand.

**Lifetime.** Every call that starts or stops the port goes through one lock; every start takes the next generation number, and a frame or stand-down from an old one is dropped. `LaunchpadEngine.activate()` starts the watch only if `pinchEnabled` is on; `deactivate()` and `deinit` stop it. Frames arrive on the framework's thread and are fed under the pinch's own lock (`pinchLock`, apart from the layout's, which a disk read holds: order `portLock`, then `pinchLock`). What a recognizer says goes to a **mailbox** and main is told once (`drain`, `onPinch`): a `moved` replaces a `moved` at the end, so a busy main holds a few events and not a hundred frames a second. **One scrub at a time**: the pad whose `began` came first owns it. **A scrub that main was told began is always told it ended**: a watch that stops inside one, or a pad that falls silent for `silenceLimit`, puts `ended(.revert)` after what is owed, under the same lock.

**The model and the window.** `pinched(_:)` keeps one `Scrub` from `began` to `ended`. A pinch with no window builds one (through `openWindow`), never `present()`s it, and hands it `beginScrub(.pinch)` and then each progress. An end that **opens** completes the window (`endScrub(.complete)`: key and search focus at once, clicks ignored until the settle arrives, as in `present()`); one that **reverts** an opening makes the model forget the window first and then closes it. Closing the window by any route sets the scrub to none, so what the fingers say later reaches no other window. The scrubbed window is shown **without becoming key**, so the app in front keeps the keyboard until the scrub completes. Not tried on a pad: that a panel at alpha 0 ticks its display link, and the cost of the alpha at 120 Hz.

**The system's own pinch.** Helm writes no trackpad setting. `SystemTrackpadPreferences` (`SystemPorts.swift`) reads `TrackpadFourFingerPinchGesture` and `TrackpadFiveFingerPinchGesture` (0 is taken as off, unverified). While the switch is on and the system's pinch is `on`, the page says so and offers "Open Trackpad Settings" (`PermissionCheck.openTrackpadSettings`; More Gestures is a tab and is not addressable), because a passive listener cannot stop the system opening Apps over the window.

## The Launchpad settings page

The page id is the module id, `launchpad`. A grouped form: a button that opens the window, the Dock-icon row (§ The Dock icon), the shortcut's row, the pinch row (§ The trackpad pinch), the grid (§ The grid settings), the hidden apps' row (Show behind the same lock, no names, the list drawn until `onDisappear`; § The Hidden block), "Moved apps: N" with "Return all" (disabled at 0, one `.returnAllToOwnCategory` write), the launch counts' Reset row (§ The category view) and "Reset arrangement", which asks first: only the dialog's destructive button resets, once, keeping what is hidden and what is moved (§ The default arrangement). A notice banner above has no button and no timer.

The Dock-icon row is there only when the helper exists (`LaunchpadViewModel.helperURL`; `AppBuild.launchpadHelperURL` is nil under `swift run`, a test host or a bundle packaged before the helper): the helper's own icon and "Show in Finder" (`HelmReveal.inFinder`), named by what Finder displays. A state of the page is shot with `bash Scripts/shoot.sh launchpad ... --name <state>-<light|dark>` as the Disk page's states are (Architecture/Disk.md § The states of the Disk page); the window is shot live in Helm Dev, and nothing on the Mac is launched or removed to reach a state.
